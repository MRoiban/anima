Items not met or approximated, and why:

- Browser audio in repeats is unresolved. `evidence/playback.json` has no starts/requests/errors; `evidence/audio-control.json` records successful root playback. CLI audio requests alone do not establish audible playback, so item 4 remains partial. The exact implementation cause was not investigated because runtime source reads were prohibited.
- Title bar width uses host-writable `titleChars`. No documented string-length expression/converter was found. It matches all initial/inserted titles, but a title-only write does not resize it: `title-limit.sample` changes title to LongerTitle while width stays 4. `data.sample` explicitly updates both fields. This is an approximation of scene geometry, not a claim of automatic title-length derivation.
- Cover and clip selection use a finite four-entry catalog inside the reusable row. New tracks can use any catalog entry; arbitrary additional assets require extending the row's declarations/bindings. Clip keys are named data, selected via guarded audio states. Selection uses unique track ids; duplicate ids would highlight together and are outside tested behavior.
- CLI `sample` cannot perform whole-list edits (`set $tracks [...]` reports a numeric-value error), so those transitions are exercised by the documented public web host API. All scalar and click behaviors have saved `anima sample` scripts; list mutation is a supplemental host test, not claimed as CLI-supported.
- CLI `render --size 480` produces a square PNG with the 480×360 scene letterboxed by 60 transparent pixels above/below. The document itself is viewBox 0 0 40 30. Browser SVG occupies 480×360 at the top of its 480-square icon box. Initial browser pointer coordinates assumed CLI letterboxing; corrected before the passing host test.

What was hardest; docs or diagnostics wrong or incomplete:

- `build --embed` only embedded root assets in this observed result: component-local PNG/WAV sources stayed relative in built JSON. Initial CLI renders silently omitted component-local images. Original failing renders `initial.png` and `built.png`, plus `initial.svg`, are retained. Embedding the tiny PNG payloads directly in authored URLs fixes rendering; WAVs remain alongside the built file and root control proves they load.
- A direct count source `$tracks.length` gave `list-source`, despite that path being readable by sample and bindings. A declared computed number works. Counter component inherited named Track instances, requiring seemingly unrelated image catalog declarations to avoid `data-asset`; those source pointers only identified the component, not the offending property.
- The authoring docs still describe data keyframes as pending in some sections but supported in others; no reliance on those contradictory claims here. `examples/page.html` linked from docs does not exist; module examples do.
- `inspect` lists 256 possible repeated input slots per input, which makes a three-row scene's output very long.
