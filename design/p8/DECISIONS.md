# P8 decisions (design lead, 2026-11-09; the owner may revisit any of them)

Citations: RAS = `docs/research/rive-animation-and-state.md`, RFG = `docs/research/rive-format-and-graph.md`,
RWR = `docs/research/rive-web-runtime.md`, GC = `docs/research/glyphy-compat.md`, "Rive docs" = local
`rive docs rigging` / `rive docs easing` / `rive schema` (CLI 1.9.1), paraphrased, never copied.

- **D1 Seven modules, nine entries, all runtime entries `heavy`** (`rig`, `ik`, `pathfollow`, `skin`, `mesh` + `canvas-mesh`, `posepad`, `scroll`; `markup-rig` authoring): pay only for what you use (PLAN size rule 4), disjoint files for parallel tickets, and `canvas` is full (5,864/5,888) so mesh drawing needs its own entry — MODULES §3.1, PLAN "heavy modules on the canvas backend".
- **D2 One rig stage after layout, before drawing; at most two solve passes (only with pose pads); no dirt-restart loop:** a static dependency order computed at load replaces Rive's dirt walk with restarts, and guards never see same-step rig output — RFG §3.2–3.4 (topological update, restart when dirt flows upstream), RAS §2.3 (up to 5 feedback passes, hard to make deterministic), P7 "previous boxes" rule.
- **D3 A node's position is its pivot in world space** (a bone's: its start); rotation/scale are the world matrix's decomposition: Anima never re-origins nodes, so the pivot is the only authored "where" — SPEC §4, RFG §6 ("no implied context").
- **D4 Art inside a bone stays in rest grid coordinates; a bone contributes `F(now)·F(rest)⁻¹`:** keeps Glyphy geometry usable as-is and every bone identity at rest — GC (no re-origining, grid geometry), SPEC §4.
- **D5 Bones outside bones are roots; `root="true"` anchors a nested chain inside a moving bone:** covers Rive's legal root-inside-bone case without a second node type — Rive docs rigging (root bones may nest).
- **D6 The bind pose is the bones' rest pose from the document; no bind matrices are authored:** Rive's docs warn a transposed bind matrix renders wrong with no diagnostic; agents should not hand-write matrices — Rive docs rigging (skinning section), RAS §C (footguns).
- **D7 Automatic weights by default: two nearest rest bone segments, `1/(d + 0.001)²`, normalized, computed per control point:** hand-authored weights are the painful part of skinning; deterministic and readable — Rive docs rigging ("take it from a designer's file"), agent-native benchmark rule.
- **D8 Weights are influence maps by bone id with 0..1 values, normalized with a `rig-weight-sum` warning; `@rest` is the identity influence:** replaces packed bytes, 1-based indices and an un-renormalized /255 sum — Rive docs rigging (Weight), RAS §C (mixed units and encodings).
- **D9 Cubic handles default to their anchor's influence; `in`/`out` set their own:** independent handle weights only where wanted (`rigging.cubic-weights`) — Rive schema CubicWeight.
- **D10 Constraint spellings are verbs (`copy-position`, `copy-rotation`, `copy-scale`, `copy-transform`, `keep-distance`, `along-path`, `spread-along-path`, `scroll`, `scroll-thumb`); `ik` keeps the generic abbreviation:** no Rive type names, readable for agents — AGENTS.md hard rules, PLAN ground rules.
- **D11 Distance modes `within` (default) / `beyond` / `exact`:** names say which side is enforced; Rive's numeric modes are undocumented in its schema — Rive docs rigging (distance modes).
- **D12 IK `bones` counts the whole chain including the constrained bone (1 = aim, 2 = two-bone):** avoids Rive's parent-count off-by-one — Rive schema IKConstraint `parentBoneCount`.
- **D13 `bend="cw"` (default) is Rive's default side, `ccw` its inverted solution; a mirrored ancestor mirrors it:** oracle parity with the native default — Rive docs rigging (IK direction).
- **D14 IK chains longer than two bones follow Rive's MIT runtime's approach, reimplemented, with a fixed iteration count and NOTICE attribution; one and two bones are our own analytic solves:** no unique answer exists for n > 2, so matching the native one is the only way to pass its oracle; fixed iterations keep results identical across runtimes — PLAN ground rules, MODULES §5.
- **D15 Strength blends decomposed transforms (pivot position, shortest-arc rotation, scale, skew) componentwise, in authored order:** later full strength overrides, partial strengths combine (`rigging.constraint-order`) — Rive docs rigging (strength 0–1), inventory row text.
- **D16 Constraint fields are addressed by index (`<node>.constraints.<k>.strength`):** the `paints.<k>` precedent, no new naming scheme — SPEC composite "Ordered paints".
- **D17 `copyPosition`/`copyRotation`/`copyScale` without `from` read the parent (world space) or identity (local space):** matches the documented "parent serves without a target"; the oracle confirms and the spec records any difference — Rive docs rigging (targets not always required).
- **D18 `copyTransform`'s point defaults to the pivot; `origin` is normalized over the node's rest bounds:** Rive's origin is relative to a re-origined component; our pivot is the equivalent — Rive schema TransformConstraint, D3.
- **D19 Along-path: open paths clamp `at` to 0..1, closed paths wrap; spread places child k of n at `start + (end − start)·k/max(n − 1, 1) + shift` and works on any node's direct children, a `repeat`'s items included:** one rule for lists and plain groups; the oracle decides the spacing denominator — Rive schema ListFollowPathConstraint.
- **D20 Path measurement is private to `pathfollow` and reuses core's outline lengths subdivision:** owner decision (no public path-measure API, inventory `drawing-paint.path-measure` won't-do); trims and following measure the same length — SPEC "Shared outline lengths".
- **D21 Browser SVG draws a meshed image undeformed and reports `unsupported-render` (feature `mesh`); static `toSVG` with `meshTriangles: true` (CLI only) emits one clipped affine image per triangle:** owner's "meshes on the canvas backend", a defined fallback instead of silence, and an exact static output for the oracle — RFG §4.2 (Rive's SVG export has no image mesh), §4.3 (meshes are a Canvas2D gap to fill by hand).
- **D22 `mesh` offers a `grid` shortcut with uv from the image's fit and align; explicit meshes ignore fit:** agents need no triangle lists for the common case and a rest grid draws exactly like the plain image — Rive docs rigging (index-buffer encoding is a failure point).
- **D23 Mesh vertices are tuple addresses `<image>.mesh.vertex.<k>` = `[x, y]`:** animatable and bindable through existing tuple sampling — SPEC §5 (tuple values).
- **D24 Canvas triangles are dilated by 0.5 device pixel before clipping:** hides anti-aliased seams between adjacent triangles deterministically — RWR (canvas backend notes), canvas RESULTS limits.
- **D25 The two-axis control is a `posePad` node with `valueX`/`valueY` in −1..1, mapped across each timeline's whole duration, written as the topmost layer:** a node gives bindable, animatable addresses for free; no Rive feature name — Rive docs easing (joysticks).
- **D26 Handle pads read the solved handle; layout sees pad output one step later:** a pose-after-solve-then-resolve order without a loop; a pad posing its own handle is `posepad-cycle` — Rive docs easing (handle becomes an output), D2.
- **D27 Scroll is minimal: clamped offsets in grid units, drag and wheel, bindable, `percentX/Y` as 0..1, a linked and optionally resized thumb; physics, snap, virtualization and infinite scroll stay won't-do:** the owner's triage of the layout scroll rows ("page CSS covers it"); fractions, not Rive's 0–100 — inventory `layout.scroll-*`, RAS §C (percent units).
- **D28 Derived `world.*`, `tip.*` and scroll percent addresses are snapshot/expect outputs, not guard operands:** keeps the step order acyclic; a guard on a hand position can come later through an explicit rule — D2.
- **D29 A skinned node ignores its own and its ancestors' animated transforms; its stroke width follows its rest world scale; skin plus an animated `d` is rejected:** the bones are the only motion source, as in Rive, where moving a skinned shape's own node has no effect — Rive docs rigging (3D section).
- **D30 My authoring cap rises from 15,360 to 15,872 B (owner ceiling 16,384 unchanged):** 343 B of headroom cannot hold any rig spelling code; P8 may add at most 768 B — PLAN size table (authoring add-on).
- **D31 R4-02 ranks by a pre-order walk with children in resolved `drawOrder`, supplied by composite as `Player.paintRank`:** a global paint order composite already resolves per sibling list; input and focus only swap their comparison key — `design/rottweiler/P4-LEDGER.md` R4-02, owner delegation 2026-11-09.
- **D32 `a11y.tree-bounds`: dash bounds stay conservative (undashed stroke) and text uses logical line boxes, both documented differences:** exact dash extents cost a dash walk per frame for at most the end gaps; platform accessibility trees and DOM text rectangles report line boxes, not ink — modules/a11y/SPEC.md "Painted geometric bounds", inventory reason.
- **D33 Pre-player `toggle()` shares the `set`/`fire` FIFO:** one queue, one order rule — SPEC "Host input queue", issue #24 decision.
- **D34 The benchmark is a reaching arm (IK + skin + distance gate + eased release); only the P4c volume brief is rerun (AniML), because R4-02 touches input and focus:** exercises the phase's main rows in one brief, regression check limited to touched modules — `docs/benchmarks/agent-native.md`.
- **D35 The mesh oracle compares Rive against `anima render` with CLI triangle output; browser canvas meshes are compared against that render in a browser test:** the oracle tooling renders through the CLI (resvg), which has no canvas — `tests/oracle/README.md`.

## Orchestrator answers (2026-11-09)

- D30 accepted: the 15,872 B authoring cap is the orchestrator's own and stays under the owner ceiling (16,384 B).
- D14 accepted: the owner's ground rules allow following an MIT solver when the spec says so and NOTICE carries the attribution; the P8-2 coder may read Rive's MIT IK source for the algorithm only and writes Anima's code independently, with no text copied.
- Unconfirmed Rive behaviours (list spacing, path wrap, copy constraints without a target): the spec's choice stands until the oracle runs; a mismatch is fixed or recorded as an intentional difference, never a widened budget.
- D36 (orchestrator, 2026-11-09, asked by P8-6): the pose-pad node type is `posepad` in JSON and `<posepad>` in AniML. Every node type is one lowercase word and the AniML element equals the type; a kebab node name would need a node-name alias seam in `markup`, which must not grow.
- D37 (orchestrator, 2026-11-09, asked by P8-6): pose-pad handle support moves to an optional `posepad-handle` entry (heavy, over `posepad`, 512 B) if `posepad` cannot fit 768 B with it (measured 1,118 B); budgets are not raised.
- D38 (orchestrator, 2026-11-09, asked by P8-1): a bone's parent is the document root, a component's root level, a `group` or a `bone`; anything else (layout, repeat, instance, text) is `rig-bone-parent` (hint: wrap the bones in a group). A bone has no box for layout to place, and this keeps rig ordering simple; widening later is compatible.
- D39 (orchestrator, 2026-11-09, asked by P8-1): a zero rest scale on a bone or any ancestor of a bone is `bad-value` (hint: use a nonzero rest scale and animate the collapse); the rest frame must be invertible (D4). Animated collapse from a nonzero rest pose stays valid.
- D40 (orchestrator, 2026-11-09, after P8-5): point tuples (`[x, y]` animatable values) live in core: +16 B core+web (22,787 → 22,803). The design assumed tuples already existed; they did not. The owner ceiling (24,576) is far away; the "rigging adds 0 B to core+web" target is mine and is relaxed for this shared value type only.
- D41 (orchestrator, 2026-11-09): budgets reset by the P3c rule (⌈measured × 1.10 / 64⌉ × 64): `mesh` 1,024 → 1,472 (1,325 measured; heavy, Rive-class), `posepad` 768 → 896 (772 after the tuple printer), `components` 3,456 → 3,840 (3,457: shared-base gzip shift, no components code change). Size exits 0.
- D42 (orchestrator, 2026-11-09): mesh oracle cases are not promoted yet. Measured max 53–82, 0.27–0.40 % over 16, far above every image-case precedent (16/2/0). The diff location (seams, edges, texture interior) is investigated first; rows `rigging.mesh` and `rigging.mesh-animation` stay planned.
- D43 (orchestrator, 2026-11-09): mesh oracle budgets 16/70/0.40 (`rigging-mesh`, measured 53/0.333 %) and 16/100/0.45 (`rigging-mesh-animation`, measured 82/0.399 %). The analysis puts every over-16 pixel on internal triangle seams or the outer edge, none in the interior; an undivided-image control drops to 0. Precedents: path-morph 65/0.4, star 80/0.45, ellipse 90/0.4.
- D44 (orchestrator, 2026-11-09): rig oracle probes use rect art (circles differ from Rive by construction; the old steady 53 pattern was that). Unrotated probes 16/2/0 (measured 1/0); rotated frames (bone-chains, root-bones, rotation, transform) 16/65/0.12, measured max 52 and ≤ 0.087 %, all on the rectangle boundary. Tighter than the coder's 65/0.4 proposal; precedent rect-corners 90/0.12.
- D45 (orchestrator, 2026-11-09): IK oracle budgets 16/65/0.25 (`rigging-ik`, `rigging-ik-bend`), measured max 59 and ≤ 0.22 %, every over-16 pixel within 1–3 px of a rectangle edge or joint overlap. Precedent path-morph 65/0.4.
- D46 (orchestrator, 2026-11-09): follow-path oracle 16/65/0.12 on a re-authored probe (asymmetric cubic, orient, animated `at`, closed-path wrap), measured max 60 and ≤ 0.057 %, edge only. List follow path stays a skip for the direct native list constraint (it does not distribute headless), but its spacing matched Rive per-child follow-path at the same distances (max 1, 0 over), recorded in the skip evidence.
- D47 (orchestrator, 2026-11-09, after P8-1b): rig adds no checks to core. A bone under a container that may not host it (layout, repeat, instance, text) is `rig-bone-parent` from the rig module; a bone under a leaf shape (no `children` field) fails core structural validation with `unknown-key`. P8-1b's core checker seam (+88 B core+web) was reverted. Rows bone-chains and root-bones done; transform stays open (origin tuple animation and binding, group-subtree origins).
- D48 (orchestrator, 2026-11-10, after P8-4): `skin` keeps explicit weights on paths and contours (1,534/1,536 B); automatic weights (`skin-auto` 320), meshed images (`skin-mesh` 256), percentage-dash recalculation (`skin-dash` 192) and derived values (`skin-values` 256) are optional heavy entries, each budgeted ⌈measured × 1.10 / 64⌉ × 64; a missing entry that changes the drawing (`skin-auto`, `skin-mesh`, `skin-dash`) is `rig-skin-feature`, never a silent no-op. `skin-values` only adds the derived `<node>.skin.point.<k>` read-outs to `values()` for tooling; without it the scene draws identically, so it has no diagnostic (a load-time error would reject valid documents). Clarified after Rottweiler R1-3; owner may revisit.
