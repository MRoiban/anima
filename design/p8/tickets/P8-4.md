# Anima P8 — shared brief (identical for every P8 agent)

Repo: Anima, an open animation format (`.ani`, AniML `.animl`) and a small web runtime (`<anima-icon>`): a smaller, agent-native Rive for animated web UI. Your checkout is a worktree on a branch made from `p8-rigging` (see `git log -1`). Read first: `AGENTS.md` (incl. `## Repo rules`, "Adding a module", "Adding a capability"), `WORKLOG.md` (Now, Owner, Gotchas), `design/p8/DESIGN.md` (the decided P8 design; your ticket is part of it), `design/p8/DECISIONS.md`, `docs/PLAN.md` "Definition of done" for a capability, `spec/MODULES.md` §3.1 and the hook sections your ticket names, and the research notes the design cites.

Hard rules (no exceptions):
- Don't copy Rive source code or Rive CLI/documentation text. Don't read, import, convert or emit `.riv` files; never touch watermark content. Don't use Rive names or branding for Anima features. Where an algorithm closely follows Rive's MIT code, say so in the spec and add attribution to NOTICE.
- Rive CLI: only `~/.rive/bin/rive` with local commands `--help`, `docs`, `schema`, `create`, `inspect`, `--verify`, headless `<dir> --commands`, `update`. Never `--publish`, `--rev`, `push`, `pull`, login/logout/whoami/library/ls/workspace/open/build/aot/switch/uninstall/samples/analytics or interactive preview. Delete scaffold files carrying Rive docs text (AGENTS.md, CLAUDE.md, .gitignore created by `rive create`), any `.riv` and capture `build/` folders before committing.
- No third-party font or image files in the repo: tests use the generated font `fixtures/fonts/anima-test.ttf` and generated images (write a small generator; commit its output only if it is tiny and original).
- Shipped packages stay dependency-free. The licence is MIT (LICENSE); don't change it. Don't publish, don't push to `main`, don't open PRs: commit on your branch only.
- Measurements belong to the orchestrator: run `node tools/size.ts`, `node tools/perf.ts`, `node tools/oracle.ts --strict` but never change them, their inputs, thresholds or budgets; never edit oracle `finding.json` or benchmark records. If a budget would be exceeded, cut code, split into an optional entry of your own module, or stop and report — never raise a budget. - Module names have no hyphens (`node tools/new-capability.ts` rejects them). Every P8 runtime entry is `heavy: true`. Install per-player hooks only for models whose `requires` lists your feature: no work in `Player.step` or the draw path for scenes that don't declare it (≤ 3 % guard).
- Generated files are regenerated, never hand-edited: `node tools/modules.ts`, `npm run gen`, `node tools/parity.ts`, `node tools/build-animl.ts`, `node tools/build-web.ts`.
- Capabilities start with `node tools/new-capability.ts <row-id> --module <your module> --dry-run`, then without it. Set a row `done` in `docs/parity/inventory.json` only when its definition of done is met (spec section, registry both spellings, diagnostics with code/pointer/message/hint and a test each, conformance case for anything that changes `Player.step` or drawing output, AniML example + `.ani`, CLI/schema support, size check, oracle case or skip note with reason, tests). Agents don't set oracle budgets: report raw max/over and leave `todo.json`; the orchestrator adds the case to `tests/oracle/cases.json` from measured anti-aliasing. A real geometry difference is fixed or recorded in the spec as an intentional difference with its reason — never a widened budget.
- Stay inside the files your ticket owns (listed below). Other agents work in parallel on the rest. Shared generated wiring, `spec/SPEC.md` (append your own `## <feature>` chapter), `docs/parity/*` (your rows only) and `NOTICE` (append) are shared: change only your parts. If you need a change outside your files, make the smallest seam, mark it `// seam(P8-N): <reason>` and list it in your report; never refactor another ticket's files.

Before your final commit: `npm run test:scope -- changed`, `node tools/modules.ts --check`, `node tools/build-animl.ts --check`, `node tools/parity.ts --check`, `node tools/size.ts` (long timeout; check its exit code), `node tools/oracle.ts --strict` if you touched oracle cases, `npm run lint`, `npx prettier --check` on changed files. ## Ticket P8-4 — skins and weights (paths, contours, meshes)

Owns: new module `modules/skin/**` (runtime entry `skin`, `heavy: true`, budget 1,536 B), its wiring,
the `## skin` chapter in `spec/SPEC.md`, conformance `spec/conformance/rigging-{skin,weights,cubic-weights}/`,
oracle probes for these rows, inventory status for these rows. Read-only: `modules/rig/**`,
`modules/mesh/**`, `modules/paint/**`, `modules/contour/**` (seams only, marked).

Rows: rigging.skin rigging.weights rigging.cubic-weights.

Depends on: P8-1 and P8-5 merged into `p8-rigging`.

Implement DESIGN §3 "Skins and weights" (D6–D9, D29):
- `skin: {bones, weights?}` on `path` (inline `d` or `glyph`), `contour` and meshed `image`;
  anything else is `rig-skin-host`; an animated `d` with a skin is `rig-skin-morph`.
- Binding = the bones' rest frames. Deformation of a node-local rest point `p`:
  `p' = W0⁻¹ · Σᵢ wᵢ · Dᵢ · W0 · p`, `Dᵢ = Bᵢ(now) · Bᵢ(rest)⁻¹` (`@rest` → identity), `W0` the node's
  rest world; the node's draw transform stays its rest world (stroke width follows the rest scale).
- Points: path — every M/L/C endpoint in order (Z adds none), cubic controls are the previous
  anchor's `out` and this anchor's `in`; contour — every vertex, its handles `in`/`out`, rounding
  constructed after deformation; mesh — every vertex.
- Automatic weights at load when `weights` is absent (D7); explicit influence maps (D8) with
  `rig-weight-count` (> 4), `rig-weight-sum` (warning, normalized), `rig-weight-bone` (bone not in
  `bones`); handles default to their anchor (D9).
- Output: a `draw.frame` hook writes the deformed geometry (path data for paths/contours; deformed
  `DrawNode.mesh.points` for meshes), paint's `outline(player, node)` returns the deformed outline
  for hit tests and a11y bounds; implement `Player.skinPoints(node, xy)` (DESIGN §5) and use it for
  meshes. Relative trims/dashes measure the deformed outline (invalidate the length cache when the
  deformation changes).
- Derived read-only address `<node>.skin.point.<k>` = world `[x, y]` for conformance.
- Example pair `modules/skin/examples/sleeve.animl` + `.ani` (the benchmark-like sleeve on two bones).

Acceptance:
- `npm run test:scope -- skin rig mesh paint contour conformance oracle --browser=chromium` green; Firefox once.
- `rigging-skin`: at rest every skinned point equals the unskinned point (1e-6); deformed points on a
  path, a contour and a meshed image under animated bones; the canvas/SVG corpus comparison passes
  (meshed image in canvas only).
- `rigging-weights`: 1, 2 and 4 influences, `@rest`, automatic weights vs hand-computed values.
- `rigging-cubic-weights`: `in`/`out` handle weights that differ from the anchor move the handles
  independently.
- Hit test follows the deformed outline (`input` hitTest on a point inside the deformed but outside
  the rest shape); a11y bounds of a skinned node follow the deformation.
- `anima bench` of `sleeve.ani` vs the same scene without `skin`: step + draw median ≤ 2× (report raw).
- Oracle probes with explicit weights only (D7 note); report raw numbers.
- `node tools/size.ts` exit 0 with `skin` ≤ 1,536 B, core+web unchanged.
