# Anima P8 — shared brief (identical for every P8 agent)

Repo: Anima, an open animation format (`.ani`, AniML `.animl`) and a small web runtime (`<anima-icon>`): a smaller, agent-native Rive for animated web UI. Your checkout is a worktree on a branch made from `p8-rigging` (see `git log -1`). Read first: `AGENTS.md` (incl. `## Repo rules`, "Adding a module", "Adding a capability"), `WORKLOG.md` (Now, Owner, Gotchas), `design/p8/DESIGN.md` (the decided P8 design; your ticket is part of it), `design/p8/DECISIONS.md`, `docs/PLAN.md` "Definition of done" for a capability, `spec/MODULES.md` §3.1 and the hook sections your ticket names, and the research notes the design cites.

Hard rules (no exceptions):
- Don't copy Rive source code or Rive CLI/documentation text. Don't read, import, convert or emit `.riv` files; never touch watermark content. Don't use Rive names or branding for Anima features. Where an algorithm closely follows Rive's MIT code, say so in the spec and add attribution to NOTICE.
- Rive CLI: only `~/.rive/bin/rive` with local commands `--help`, `docs`, `schema`, `create`, `inspect`, `--verify`, headless `<dir> --commands`, `update`. Never `--publish`, `--rev`, `push`, `pull`, login/logout/whoami/library/ls/workspace/open/build/aot/switch/uninstall/samples/analytics or interactive preview. Delete scaffold files carrying Rive docs text (AGENTS.md, CLAUDE.md, .gitignore created by `rive create`), any `.riv` and capture `build/` folders before committing.
- No third-party font or image files in the repo: tests use the generated font `fixtures/fonts/anima-test.ttf` and generated images (write a small generator; commit its output only if it is tiny and original).
- Shipped packages stay dependency-free. The licence is MIT (LICENSE); don't change it. Don't publish, don't push to `main`, don't open PRs: commit on your branch only.
- Measurements belong to the orchestrator: run `node tools/size.ts`, `node tools/perf.ts`, `node tools/oracle.ts --strict` but never change them, their inputs, thresholds or budgets; never edit oracle `finding.json` or benchmark records. If a budget would be exceeded, cut code, split into an optional entry of your own module, or stop and report — never raise a budget. Owner gates (min+gzip, main c2b870ae): core+web ≤ 24,576 (now 22,782; rigging adds 0 B), each scene ≤ 65,536 (largest 57,781), app-UI ≤ 131,072 (107,899), runtime sum ≤ 163,840 (135,579), authoring ≤ 16,384 (15,017; P8 cap 15,872), Rive-class ≤ 256,000 (155,805), each entry ≤ its budget and never above 8,192. Full now (no growth without a split first): `canvas` 5,864/5,888, `focus` 3,374/3,456, `components` 3,453/3,456, `markup-libraries` 2,174/2,176, `markup-hooks` 4,523/4,544, `fonts-info` 8,100/8,192. `markup` (7,435) must not grow: AniML spellings that need code go in `markup-rig` (P8-1) or nowhere — other tickets use registry-generic spellings (JSON-valued attributes for compound fields, as `contour` does).
- Module names have no hyphens (`node tools/new-capability.ts` rejects them). Every P8 runtime entry is `heavy: true`. Install per-player hooks only for models whose `requires` lists your feature: no work in `Player.step` or the draw path for scenes that don't declare it (≤ 3 % guard).
- Generated files are regenerated, never hand-edited: `node tools/modules.ts`, `npm run gen`, `node tools/parity.ts`, `node tools/build-animl.ts`, `node tools/build-web.ts`.
- Capabilities start with `node tools/new-capability.ts <row-id> --module <your module> --dry-run`, then without it. Set a row `done` in `docs/parity/inventory.json` only when its definition of done is met (spec section, registry both spellings, diagnostics with code/pointer/message/hint and a test each, conformance case for anything that changes `Player.step` or drawing output, AniML example + `.ani`, CLI/schema support, size check, oracle case or skip note with reason, tests). A row you can't close: leave it planned and say exactly what's missing.
- Oracles: follow `tests/oracle/README.md`. Rive scenes encode Anima's semantics (DESIGN §10 risk 1: art inside bones converted into bone space; rotations in radians; 12 px/unit). Agents don't set oracle budgets: report raw max/over and leave `todo.json`; the orchestrator adds the case to `tests/oracle/cases.json` from measured anti-aliasing. A real geometry difference is fixed or recorded in the spec as an intentional difference with its reason — never a widened budget.
- Stay inside the files your ticket owns (listed below). Other agents work in parallel on the rest. Shared generated wiring, `spec/SPEC.md` (append your own `## <feature>` chapter), `docs/parity/*` (your rows only) and `NOTICE` (append) are shared: change only your parts. If you need a change outside your files, make the smallest seam, mark it `// seam(P8-N): <reason>` and list it in your report; never refactor another ticket's files.
- Tests while coding: `npm run test:scope -- <targets…> --browser=chromium`; Firefox once at the end for your browser suites (new browser test files need an explicit 30 s timeout). Before your final commit: `npm run test:scope -- changed`, `node tools/modules.ts --check`, `node tools/build-animl.ts --check`, `node tools/parity.ts --check`, `node tools/size.ts` (long timeout; check its exit code), `node tools/oracle.ts --strict` if you touched oracle cases, `npm run lint`, `npx prettier --check` on changed files. Never `--no-verify`. The machine is shared by 4–5 agents: a timeout that passes rerun alone is load; report both runs. A fresh worktree needs `npm ci` first.
- Work loop: measure, change, measure, keep or revert. Timebox ~3 hours; then commit what works and report what's left.
- Notes: keep checkpoint lines in your own report file `modules/<module>/<TICKET>-REPORT.md` (`- 2026-11-xx HH:MM: did X → result (evidence)`); don't edit `WORKLOG.md`. Commit the report with the code.
- Honesty: report failures, skipped steps and anything unverified plainly. A partial result reported honestly is better than a claimed success.

Final report (your last message), in this order: status (done / partial / blocked); branch and head SHA; rows closed (ids) and rows left with what's missing; seams outside your files; verify results (commands + pass/fail counts, both engines); sizes before → after for every entry you touched and all six gates; deviations from the design with reasons; problems.

## Ticket P8-1 — rig core: bones, world solve, ordered constraints

Owns: new module `modules/rig/**` (runtime entry `rig`, `heavy: true`, budget 3,072 B; authoring entry
`markup-rig`, budget 384 B, `over: 'markup'`), its generated wiring, the `## rig` chapter in
`spec/SPEC.md` plus the **rig stage** paragraph in SPEC §7 (after the layout stage, before drawing),
conformance cases `spec/conformance/rigging-{bone-chains,root-bones,constraint-order,constraint-strength,translation,rotation,scale,transform,distance-closer,distance-further,distance-exact}/`,
oracle probes `tests/oracle/rigging-*` for the same rows, and inventory status/evidence for these rows.
Not: `modules/ik|pathfollow|skin|mesh|posepad|scroll/**`.

Rows: rigging.bone-chains rigging.root-bones rigging.constraint-order rigging.constraint-strength rigging.translation rigging.rotation rigging.scale rigging.transform rigging.distance-closer rigging.distance-further rigging.distance-exact.

Depends on: nothing (wave 1). P8-2, P8-3, P8-4, P8-7 build on this ticket: make your **first commit**
`modules/rig/core/api.ts` with the DESIGN §5 contract (`registerConstraint`, `RigContext`, `blend`,
`position`, `Model.rigPose` call site) so the seam is reviewable early; don't change it later without
listing the change in your report.

Implement DESIGN §3 (bones, constraints table rows for the five rig kinds, diagnostics `rig-cycle`,
`rig-target`, `rig-bone-parent`, `rig-bone-offset`, `rig-bone-pivot`) and §4 exactly:
- Bones as `type: "bone"` nodes; rest frames from document values; children follow `F(now)·F(rest)⁻¹`
  (D4); roots per D5; a node's position is its world pivot (D3).
- Dependency order computed once at load (parent, constraint targets, `writes()` chains), cycle →
  `rig-cycle` at the constraint that closes it. Solve in `afterStep`, chained **after** layout's (put
  `layout` in the manifest's `after` so the wrapper order is fixed); per-player `p.local` override for
  solved nodes only (draw, hits, a11y follow); skip the solve when no value or layout box it reads
  changed; call `model.rigPose?.(p)` after the first pass and solve once more if it returns true.
- Constraints in authored order with `blend` (D15); fields and defaults per the DESIGN table; spaces
  `world|local`; `limitSpace`; `offset`; no `from` per D17; `copyTransform` origin per D18; distance
  modes per D11. Addresses `<node>.constraints.<k>.<field>` animatable/bindable where italic (D16).
- Derived read-only addresses `<node>.world.x|y|rotate|scaleX|scaleY` and `<bone>.tip.x|y`, selectable
  in `snapshot`/`expect` (the layout `layoutBox` precedent), not guard operands (D28).
- AniML: `<bone>` and the constraint child elements through the registry; put code in `markup-rig`
  only where the generic node-field path can't express a spelling.
- Example pair `modules/rig/examples/arm.animl` + `.ani` (a two-bone arm with rigid art, a
  `copy-position` with strength 0.5 and a `keep-distance` gate). If `rig` would exceed 3,072 B, split
  `keepDistance` into an optional `rig-distance` entry of this module (≤ 512 B) rather than cutting rows.
