## Ticket P8-7 — scroll constraint and linked thumb

Owns: new module `modules/scroll/**` (runtime entry `scroll`, `heavy: true`, budget 1,024 B), its
wiring, the `## scroll` chapter in `spec/SPEC.md`, conformance `spec/conformance/rigging-scroll/`
(more `rigging-scroll-*` cases as needed), its oracle probe, inventory status for `rigging.scroll`.
Read-only: `modules/rig/**`, `modules/input/**`, `modules/layout/**` (seams only, marked).

Rows: rigging.scroll.

Depends on: P8-1 merged into `p8-rigging`. Uses `input` (declared in `requires`) for drag and wheel;
without `input`, offsets change only through binds and timelines.

Implement DESIGN §3 `scroll` / `scrollThumb` (D27), through `registerConstraint`:
- `scroll` on the content node: `viewport` (a node; its layout box if it is a layout container, else
  its rest local bounds), `axis` `x`|`y`|`both`, `offsetX`/`offsetY` in grid units, clamped to
  `[0, max(0, content − viewport)]` per axis (content = the content subtree's rest bounds or layout
  box), applied as a translation `−offset`; `interactive` (default true).
- Interaction (input module): a drag that starts inside the viewport moves the offset by the pointer
  delta; wheel/trackpad scroll over the viewport adds its delta and is consumed only when the offset
  actually moved (input's scroll-hit policy). Offsets are per-player state changed only by queued
  input in step 1; a bound or animated offset overrides interaction each step (documented).
- Read-only `percentX`/`percentY` (0..1) as derived addresses.
- `scrollThumb` on the thumb node: `scroll` (content node id), `track` (node), `axis`, `resize`
  (thumb length = track × viewport/content, at least the thumb's authored length): the thumb's
  position along the track follows the percent; dragging the thumb sets the percent.
- No physics, snap, virtualization, infinite or elastic behaviour (those rows stay won't-do; don't
  add their spellings). The author clips the viewport with composite's clip (show it in the example).
- Diagnostics: `scroll-viewport` (missing or unmeasurable viewport); `rig-target` for an unknown thumb
  `scroll` id. One test each.
- Example pair `modules/scroll/examples/list.animl` + `.ani` (a clipped column of rows, a thumb).

Acceptance:
- `npm run test:scope -- scroll rig input layout conformance oracle --browser=chromium` green; Firefox once.
- `rigging-scroll`: `pointer drag` and `scroll` script commands move and clamp the offset; a bound
  offset; percent values; thumb position and resize; thumb drag sets the offset; `settled` true right
  after each interaction.
- Browser (both engines): wheel over the viewport scrolls the content and is prevented only while
  the offset moves; at the end of the range the page scrolls.
- Oracle: a Rive scroll scene with keyed offsets vs Anima bound offsets at the same frames; if the
  native scroll needs layout content Anima can't mirror, write a skip note with the evidence.
- `node tools/size.ts` exit 0 with `scroll` ≤ 1,024 B, `input` unchanged, core+web unchanged.
