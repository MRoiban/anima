Repo: Anima, an open animation format (`.ani`, AniML `.animl`) and a small web runtime (`<anima-icon>`): a smaller, agent-native Rive for animated web UI. Your checkout is a worktree on a branch made from `p8-rigging` (see `git log -1`). Read first: `AGENTS.md` (incl. `## Repo rules`, "Adding a module", "Adding a capability"), `WORKLOG.md` (Now, Owner, Gotchas), `design/p8/DESIGN.md` (the decided P8 design; your ticket is part of it), `design/p8/DECISIONS.md`, `docs/PLAN.md` "Definition of done" for a capability, `spec/MODULES.md` §3.1 and the hook sections your ticket names, and the research notes the design cites.

Hard rules (no exceptions):

Never `--publish`, `--rev`, `push`, `pull`, login/logout/whoami/library/ls/workspace/open/build/aot/switch/uninstall/samples/analytics or interactive preview. Delete scaffold files carrying Rive docs text (AGENTS.md, CLAUDE.md, .gitignore created by `rive create`), any `.riv` and capture `build/` folders before committing.
- No third-party font or image files in the repo: tests use the generated font `fixtures/fonts/anima-test.ttf` and generated images (write a small generator; commit its output only if it is tiny and original).
- Shipped packages stay dependency-free. The licence is MIT (LICENSE); don't change it. Don't publish, don't push to `main`, don't open PRs: commit on your branch only.
- Measurements belong to the orchestrator: run `node tools/size.ts`, `node tools/perf.ts`, `node tools/oracle.ts --strict` but never change them, their inputs, thresholds or budgets; never edit oracle `finding.json` or benchmark records. If a budget would be exceeded, cut code, split into an optional entry of your own module, or stop and report — never raise a budget. Set a row `done` in `docs/parity/inventory.json` only when its definition of done is met (spec section, registry both spellings, diagnostics with code/pointer/message/hint and a test each, conformance case for anything that changes `Player.step` or drawing output, AniML example + `.ani`, CLI/schema support, size check, oracle case or skip note with reason, tests). - Stay inside the files your ticket owns (listed below). Other agents work in parallel on the rest. Shared generated wiring, `spec/SPEC.md` (append your own `## <feature>` chapter), `docs/parity/*` (your rows only) and `NOTICE` (append) are shared: change only your parts. ## Ticket P8-5 — image meshes and mesh animation (canvas drawing, SVG fallback)

Owns: new module `modules/mesh/**` (runtime entry `mesh`, `heavy: true`, budget 1,024 B, with its SVG
backend; runtime entry `canvas-mesh`, `heavy: true`, `over: 'canvas'`, budget 768 B), its wiring, the
`## mesh` chapter in `spec/SPEC.md`, conformance `spec/conformance/rigging-{mesh,mesh-animation}/`
(with `unsupported-svg.json` for the SVG backend), oracle probes for both rows, a generated original
test image under `modules/mesh/test/fixtures/` (small, written by a committed generator), inventory
status for these rows. Seams (marked `// seam(P8-5)`): the type-only `DrawNode.mesh` field in core's
draw types; the CLI `render` passing `meshTriangles: true` to `toSVG`.

Rows: rigging.mesh rigging.mesh-animation.

Depends on: nothing (wave 1). Skinned meshes are P8-4's: call `p.skinPoints?.(node, xy)` when present
(DESIGN §5) and leave the skinned-mesh tests to P8-4.

Implement DESIGN §3 "Meshes" (D21–D24, D35):
- `mesh` on `image` only (`rig-mesh-host` otherwise): `{grid: [cols, rows]}` → vertices over the box,
  uv from the image's fit/align (SPEC "Image nodes") so a rest grid draws like the plain image;
  explicit `{vertices, triangles}` (uv 0..1, `bad-value`; indices < vertex count and ≥ 1 triangle,
  `rig-mesh-index`); explicit meshes ignore fit/align.
- Vertex addresses `<image>.mesh.vertex.<k>` = `[x, y]`, animatable and bindable tuples.
- Draw data: `DrawNode.mesh = {points, uv, triangles}` beside the existing image geometry.
- `canvas-mesh`: a `canvasShapes` hook drawing each triangle as a clipped affine `drawImage`, clip
  triangle dilated by 0.5 device px (D24); keep its own image cache and request a redraw on load
  through the renderer's existing readiness path — **no bytes added to `canvas`** (5,864/5,888).
- Browser SVG: draw the undeformed image and report `unsupported-render` once per node (feature
  `mesh`, pointer `/nodes/…/mesh`, hint to use `renderer="canvas"`).
- Static `toSVG(…, {meshTriangles: true})` (tooling, imported by the CLI only, not in any web entry):
  one `<clipPath>` triangle + transformed `<image>` per triangle; the CLI's `render` uses it.
- Example pair `modules/mesh/examples/flag.animl` + `.ani` (a 4×2 grid mesh whose vertices wave).

Acceptance:
- `npm run test:scope -- mesh canvas conformance oracle --browser=chromium` green; Firefox once.
- `rigging-mesh`: grid and explicit meshes; drawn vertices/uv checked against independent values
  (module drawing-conformance test, the text-input `drawing.expected.json` precedent).
- `rigging-mesh-animation`: animated vertex tuples at ≥ 3 times; bound vertex.
- Browser (both engines): canvas mesh pixels vs the CLI triangle render of the same frame within the
  canvas corpus tolerance; SVG fallback shows the undeformed image and exactly one
  `unsupported-render` diagnostic.
- Oracle probes vs Rive image meshes using the generated image; report raw numbers.
- `node tools/size.ts` exit 0 with `mesh` ≤ 1,024, `canvas-mesh` ≤ 768, `canvas` unchanged.
