Repo: Anima, an open animation format (`.ani`, AniML `.animl`) and a small web runtime (`<anima-icon>`): a smaller, agent-native Rive for animated web UI. Your checkout is a worktree on a branch made from `p6` (see `git log -1`). Read first: `AGENTS.md` (incl. `## Repo rules`), `WORKLOG.md` (Now, Gotchas, last 15 Log lines), `design/p6/DESIGN.md` (the decided P6 design; your ticket is part of it), `docs/PLAN.md` "Definition of done" for a capability, and the wave-1 reports `modules/text/REPORT.md`, `modules/fonts/REPORT.md`, `packages/cli/P6-2-REPORT.md`.

Hard rules (no exceptions):

Never `--publish`, `--rev`, `push`, `pull`, login/logout/whoami/library/ls/workspace/open/build/aot/switch/uninstall/samples/analytics or interactive preview. Delete scaffold files carrying Rive docs text (AGENTS.md, CLAUDE.md, .gitignore created by `rive create`), any `.riv` and capture `build/` folders before committing.
- No third-party font files in the repo: tests use the generated font `fixtures/fonts/anima-test.ttf` from `tools/test-font.ts`.
- Shipped packages stay dependency-free. No licence file. Don't publish, don't push to `main`, don't open PRs: commit on your branch only.
- Measurements belong to the orchestrator: run `node tools/size.ts`, `node tools/perf.ts`, `node tools/oracle.ts --strict` but never change them, their inputs, thresholds or budgets; never edit oracle `finding.json` or benchmark records. If a budget would be exceeded, cut code, split into an optional entry of your own module, or stop and report — never raise a budget. Set a row `done` in `docs/parity/inventory.json` only when its definition of done is met (spec, registry both spellings, diagnostics with tests, conformance case if `Player.step`/drawing output changes, AniML example + `.ani`, CLI support, size check, oracle case or skip note with reason). ## Ticket P6-13 — variable axes and OpenType features on text styles

Owns: `modules/text/core/registry.ts` (style fields) only as far as `text` stays ≤ 6,144 B (it is 6,136 B: put new code in `fonts-text`, `fonts` or a new optional entry and register the fields from there if the registry allows extension; otherwise move an equal amount out of `text`), `modules/fonts/**` (incl. `fonts-text`), `modules/text-effects/**` only for animating the `wght`/axis values it already draws, `packages/cli/src/font/**` (tool measurer/render for axes/features), their tests, conformance and oracle cases, `docs/parity/inventory.json` notes for the rows below. Not `packages/cli/src/` outside `font/`, not `packages/markup/src/**` diagnostics, not docs guides (P6-12 is editing those; put your docs in `modules/fonts/SPEC.md` and `modules/text/SPEC.md`).

Rows: text.variable-axes text.opentype-features (and, if the work covers them, text.font-metrics text.font-decoding text.modifier-variation).

Gap (`tests/oracle/P6-9b-REPORT.md`, `tests/oracle/P6-9a-REPORT.md`): the design (§2, §6) promises variable axes (`font-variation-settings`) and OpenType features (`font-feature-settings`) on text styles, and the fonts runtime's `cssFont` already projects `FontSpec.axes`/`features` to CSS, but the authored text-style registry rejects `axes`/`features`, so nothing can be authored, bound or animated. Make them authorable in both spellings (e.g. `<style axes="wght 600, wdth 80" features="liga 0, tnum 1"/>` and JSON objects), bindable/animatable for axis values, drawn by SVG/canvas (canvas: as far as the platform allows — document limits), measured by the tool reader at the given axis values (named or interpolated per the P6-2 reader's `fvar`/`gvar` support), with diagnostics for unknown tags/values. Canvas arbitrary axes: support them if the platform does (`ctx.fontVariationSettings` doesn't exist everywhere — feature-detect, document the fallback). Native comparisons with the generated test font's `wght` axis where Rive can express them; otherwise evidenced skip notes.
