## Ticket P6-10 — string functions for bind expressions (search filtering)

Owns: `modules/bind/**` (expression language, its spec section, tests), `docs/AUTHORING.md` and the `anima docs` recipe source for data/bindings, a new example pair under `modules/bind/examples/`. Not `modules/text-input/**`, `modules/text/**`, `packages/cli/**` (P6-9b), not `docs/benchmarks/**`.

Why: the P6 search-card benchmark (`docs/benchmarks/runs/2026-11-08-p6/search-animl/REPORT.md`) needed a JavaScript host helper for "a row is shown only when its label contains the query (case-insensitive)", because the bind/derive expression vocabulary has string equality but no substring search or case folding (functions today: `min max clamp mix floor mod` in `modules/bind/core/expression.ts`). Rive met the item; AniML must too.

Decided (owner may revisit): add `contains(text, part)` → bool (empty `part` is true) and `lower(text)` → string (Unicode `toLowerCase`, locale-independent), usable everywhere bind expressions are (bindings, set actions, derive, guards). Typed: wrong operand types are load-time diagnostics with code, pointer, message, hint and tests. Keep `bind` within its budget (1,824/2,048 B today; target ≤ +120 B); if it doesn't fit, stop and report the measured cost.

Done when: spec section for bind lists the new functions with types; registry/both spellings unchanged otherwise; diagnostics tested; a conformance case where a derived visibility and a derived count follow `contains(lower($labelN), lower($query))` in the same step as the `$query` write; `anima docs` gains a short "Filtering a list by typed text" recipe (field → `$query` → derived `shownN` and `count`, using `contains`/`lower`; one AniML example under `modules/bind/examples/` with its `.ani`); the AniML corpus/AUTHORING checks pass.
