# Anima P7 — shared brief (identical for every P7 agent)

Repo: Anima, an open animation format (`.ani`, AniML `.animl`) and a small web runtime (`<anima-icon>`): a smaller, agent-native Rive for animated web UI. Your checkout is a worktree on a branch made from `p7` (see `git log -1`). Read first: `AGENTS.md` (incl. `## Repo rules`), `WORKLOG.md` (Now, Gotchas, last 15 Log lines), `design/p7/DESIGN.md` (the decided P7 design; your ticket is part of it), `docs/PLAN.md` "Definition of done" for a capability, and `docs/parity/P6-closure.md`.

Hard rules (no exceptions):
- Don't copy Rive source code or Rive CLI/documentation text. Don't read, import, convert or emit `.riv` files; never touch watermark content. Don't use Rive names or branding for Anima features. Where an algorithm closely follows Rive's MIT code, say so in the spec and add attribution to NOTICE.
- Rive CLI: only `~/.rive/bin/rive` with local commands `--help`, `docs`, `schema`, `create`, `inspect`, `--verify`, headless `<dir> --commands`, `update`. Never `--publish`, `--rev`, `push`, `pull`, login/logout/whoami/library/ls/workspace/open/build/aot/switch/uninstall/samples/analytics or interactive preview. Delete scaffold files carrying Rive docs text (AGENTS.md, CLAUDE.md, .gitignore created by `rive create`), any `.riv` and capture `build/` folders before committing.
- No third-party font files in the repo: tests use the generated font `fixtures/fonts/anima-test.ttf` from `tools/test-font.ts`.
- Shipped packages stay dependency-free. The licence is MIT (LICENSE); don't change it. Don't publish, don't push to `main`, don't open PRs: commit on your branch only.
- Measurements belong to the orchestrator: run `node tools/size.ts`, `node tools/perf.ts`, `node tools/oracle.ts --strict` but never change them, their inputs, thresholds or budgets; never edit oracle `finding.json` or benchmark records. If a budget would be exceeded, cut code, split into an optional entry of your own module, or stop and report — never raise a budget. Owner gates (min+gzip): core+web ≤ 24,576 (now 21,165), each scene ≤ 65,536, app-UI ≤ 131,072 (now 99,988), runtime sum ≤ 163,840 (122,300), authoring ≤ 16,384 (14,808; my cap 15,360), Rive-class ≤ 256,000 (132,306), each module ≤ its budget, never above 8,192. Tight now: `text` 5,578/6,144 (keep it ≤ 5,632), `markup-libraries` 2,176/2,176 (full), `markup` 7,341 (must not grow: new AniML goes in your module's own `markup-*` entry).
- Generated files are regenerated, never hand-edited: `node tools/modules.ts`, `npm run gen`, `node tools/parity.ts`, `node tools/build-animl.ts`, `node tools/build-web.ts`.
- Capabilities start with `node tools/new-capability.ts <row-id> --dry-run`, then without it. Set a row `done` in `docs/parity/inventory.json` only when its definition of done is met (spec, registry both spellings, diagnostics with tests, conformance case if `Player.step`/drawing output changes, AniML example + `.ani`, CLI support, size check, oracle case or skip note with reason). A row you can't close: leave it planned and say exactly what's missing.
- Stay inside the files your ticket owns (listed below). Other agents work in parallel on the rest. If you need a change outside your files, make the smallest seam, mark it `// seam(P7-N): <reason>` and list it in your report; never refactor another ticket's files.
- Tests while coding: `npm run test:scope -- <targets…> --browser=chromium`; Firefox once at the end for your browser suites. Before your final commit: `npm run test:scope -- changed`, `node tools/modules.ts --check`, `node tools/size.ts` (long timeout), `node tools/oracle.ts --strict` if you touched oracle cases, `npx prettier --check` on changed files. Never `--no-verify`. The machine is shared by 4–5 agents: a timeout that passes rerun alone is load; report both runs.
- Work loop: measure, change, measure, keep or revert. Timebox ~3 hours; then commit what works and report what's left.
- Append one line per checkpoint to `WORKLOG.md` Log (`- 2026-11-07 HH:MM [P7-N]: did X → result (evidence)`); don't rewrite Now or Gotchas. Commit the log with the code.
- Honesty: report failures, skipped steps and anything unverified plainly. A partial result reported honestly is better than a claimed success.

Final report (your last message), in this order: status (done / partial / blocked); branch and head SHA; rows closed (ids) and rows left with what's missing; seams outside your files; verify results (commands + pass/fail counts, both engines); sizes before → after for every entry you touched and all six gates; deviations from the design with reasons; problems.
