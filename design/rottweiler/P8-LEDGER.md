# P8 Rottweiler ledger

Phase P8 (rigging, plus carry-overs), branch `p8-rigging` against `origin/main` (97b509f3). Review
scope: the runtime and tooling source in `design/rottweiler/P8-SCOPE.txt`, with tests, docs, oracle
fixtures, probes and generated wiring excluded. One reviewer per round, on Codex Web (GPT-5.6 Sol
Web, medium; owner's provider rule). The orchestrator verifies each finding, then either fixes it
with the smallest change plus a regression test, or pushes back with the reason.

| id | severity | finding | outcome |
| --- | --- | --- | --- |
| O-1 | major | Found by the full check (`module-order.test.ts`), not the reviewer: P8 modules patched `Player` in an arrival-order-dependent way. Scroll set a sticky flag even when `input()` did not exist yet, so a later `input` install dropped its wrapper and drag/wheel never moved the offsets; rig and skin wrapped `values()` once each (first-arrival key order); scroll re-wrapped `values()` on every re-init. | fixed: scroll wraps `input()` only when present and marks the wrapper itself; rig owns one `values()` wrapper and calls `valueProviders` (cleared per init, registered by skin and scroll in dependency order). Regression: `packages/core/test/module-order.test.ts` (12 arrival orders now identical) |
| R1-1 | major | Round 1: IK threw `Cannot read properties of null` when a chain bone's world frame collapsed (e.g. an ancestor's scale animated to 0): `invert()` returned null and was dereferenced. | fixed: the IK solve skips a chain with a singular frame and keeps its pose. Regression: `modules/ik/test/core/solver.test.ts` (collapse to zero scale) |
| R1-2 | major | Round 1: scroll treated an offset as driven whenever any timeline in the document targeted it, so a dormant timeline (no state plays it) disabled drag and wheel scrolling. | fixed: an offset is driven only while `Player.writes()` lists it (current layer writes, fading writes, bindings). Regression: `modules/scroll/test/core/runtime.test.ts` (dormant timeline) |
| R1-3 | major | Round 1: without the `skin-values` entry, skinned `values()` read-outs are missing silently, against D48's "never a silent no-op". | pushed back: `skin-values` only adds derived `<node>.skin.point.<k>` read-outs for tooling; the scene draws identically without it, and a diagnostic would reject valid documents. D48 reworded to say which entries are diagnosed |
| R1-4 | minor | Round 1: `copyTransform` accepted `limitSpace` and ignored it; the spec lists only `fromSpace`/`toSpace` for it. | fixed: `limitSpace` is part of the component-copy shapes only, so `copyTransform` reports `unknown-key`. Regression: `modules/rig/test/core/diagnostics.test.ts` |
