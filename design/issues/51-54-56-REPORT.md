## #51 `inspect --summary` follows `$parent` reads

### Repro

`design/issues/proof/51-parent.animl` defines a list item component that reads the parent `Board.mark` property through `$parent.mark`, while `Board.stroke` is genuinely unused. Before the fix, summary inspection reported both properties as unused.

### Cause

The summary usage analysis tracked reads in the component's own model context but did not map `$parent` references from component instances back to the enclosing parent model context.

### Fix

`packages/cli/src/inspect-summary.ts` now tracks component-to-parent model contexts and resolves `$parent.<property>` reads against those enclosing models. Normal unused-property detection remains unchanged, so `Board.stroke` is still reported.

### Proof

- `design/issues/proof/51-before.txt`
- `design/issues/proof/51-after.txt`
- `design/issues/proof/51-after-inspect.txt`
- `design/issues/proof/51-parent.animl`

The direct after proof reports only `/data/models/Board/properties/stroke` as unused.

### Decision

Decided: count `$parent` reads as uses only when the component is instantiated under a parent context that resolves the property. This avoids hiding genuinely unused properties. Owner may revisit if summary analysis later gains a more general symbolic path resolver.

## #54 `new --glyph` preserves filled/stroked SVG structure

### Repro

`design/issues/proof/54-cutout.svg` contains a filled body plus a stroked cut-out/detail. The old `new --glyph` path flattened the SVG through glyph-path extraction, dropping the body shape and treating the open stroke as filled geometry, while `anima import` preserved the SVG correctly.

### Cause

`new --glyph` used a separate glyph extraction path instead of the SVG importer used by `anima import`. That path was suitable for compact single-path glyphs but lost paint/stroke structure in richer SVGs.

### Fix

`packages/cli/src/scaffold.ts` now imports SVG glyph input through `importSVG(...)`. `packages/cli/src/cli.ts` uses the new scaffold path. For compatible single-path glyphs, the existing compact scaffold output is retained; richer multi-shape/painted/stroked SVGs keep the importer document structure.

### Proof

- `design/issues/proof/54-before.txt`
- `design/issues/proof/54-after.txt`
- `design/issues/proof/54-after-compare.txt`
- `design/issues/proof/54-cutout.svg`

The after comparison is pixel exact: 0 differing pixels, 0 pixels beyond tolerance, max channel difference 0, and `pass: true`.

### Decision

Decided: preserve the legacy compact single-path scaffold where the SVG is compatible, and use the importer document for richer SVGs. This keeps existing single-path output stable while sharing the correct import semantics for complex glyphs.

## #56 CLI follow-ups

### Repro

The proof fixtures cover four independent problems: dark contact-sheet backgrounds produced dark, low-contrast labels; missing Firefox was treated as a required doctor failure and its hint named the wrong environment variable; session snapshots appeared in both `snapshots` and `output`; and a fresh tarball install occupied about 53 MB.

### Cause

The sheet renderer used a fixed dark label color. Doctor did not distinguish optional Firefox availability from required Chromium availability and reused the Chromium hint. Session output appended snapshot events after already collecting them in the dedicated snapshot array. The CLI package directly ships several large browser/render/build dependencies.

### Fix

- `packages/cli/src/render.ts`: contact-sheet label color now derives from background luminance, selecting light text for dark backgrounds and dark text for light backgrounds.
- `packages/cli/src/doctor.ts` and `packages/cli/src/cli.ts`: Firefox is warning-only when absent, the hint names `FIREFOX_PATH`, Chromium remains required, and text output displays warning status distinctly.
- `packages/cli/src/session.ts`: snapshot entries remain in the documented `snapshots` array and are filtered from `output`, so each snapshot is emitted once while preserving both JSON keys.
- No dependency changes were made for footprint work.

### Proof

- `design/issues/proof/56-after.txt`

- `design/issues/proof/56-after.png`

- `design/issues/proof/56-session-after.txt`

The direct doctor proof shows Firefox as `severity: "warning"` with a `FIREFOX_PATH` hint. The session proof shows one snapshot in `snapshots` and an empty `output`. The visual after proof shows light labels on `#111111`.

### Install footprint

`npm run pack` produced:

- `animl-0.1.0.tgz`: 2,825,714 B packed, 8,167,366 B unpacked
- `animl-cli-0.1.0.tgz`: 748,989 B packed, 3,434,250 B unpacked

Installing the CLI tarball in a fresh temporary package produced a 53 MB `node_modules` tree (`46,530,971` bytes by `du -sb`). Largest contributors were approximately:

- `playwright-core`: 14 MB
- `@esbuild`: 11 MB
- `animl`: 12 MB on disk, 8,167,366 B package contents
- `animl-cli`: 7 MB on disk, 3,434,250 B package contents
- `@resvg`: 4.3 MB
- `terser`: 2.4 MB
- `pngjs`: 704 KB

Recommendation: consider making browser/render-heavy dependencies optional or lazily installed, especially `playwright-core` and native `@resvg/resvg-js`. `esbuild` is also a major contributor through its platform binary. Any such packaging change should be handled separately because this issue explicitly requested measurement and recommendation only.

### Decisions

Decided: `snapshots` remains the canonical session snapshot collection and `output` excludes duplicate snapshot events, preserving the documented JSON shape without double emission. Decided: Firefox is optional for doctor success when Chromium and other required checks pass. Owner may revisit dependency packaging separately.
