# P7-1 — text split and layout measurement

Status: done (the broad run's load failures clear on isolated reruns). Branch `t3/p7-1`, based on `049f5d66`.

No parity rows are assigned or changed. The P6 carry-overs remain with P7-6.

The text module owns two new optional entries:

- `web/text-canvas` contains the original canvas drawer and is imported by `web/canvas`.
- `web/text-overflow` contains the original fit, font-size bisection, hidden and ellipsis policies.
  It includes `web/text` and installs its callback on the active registered text module.
  The layout builder passes its registered measurer into the callback, so independently emitted
  entries preserve custom measurements, font settings and readiness.

`measureText(player, nodeId, maxWidth?)` uses the text module retained by the player's model.
It returns the existing layout box and first visible baseline in local grid units. Width-constrained
probes reuse the same layout algorithm, active measurer, fonts preparation and resolved player input,
without replacing the drawing cache or changing authored data. Unknown and non-text nodes return
undefined. The helper supports both local ids and indices; the spec documents width and sizing rules.

## Design decisions and limitations

Canvas-only extraction measured 5,906 B; extracting fitting as well measured 5,782 B, both above
5,632 B. The optional overflow entry therefore groups the unchanged fitting and ellipsis/hidden
policies. Visible and clipped text remain in the base entry. CLI and core tooling automatically
retain all policies. SVG hosts using the extracted modes need the documented overflow import.
The renderer split follows `docs/research/rive-web-runtime.md` §1; no external implementation was copied.

The actual measured baseline authoring gate is 14,742 B, versus 14,717 B in the design table.
The repository measurement is authoritative. Performance timings taken under shared machine load
cannot establish the ≤3% guard; the orchestrator owns that measurement.
