# [P3b-9] Logical-tree action and property observations

The original roles/ scene and its three raw captures are unchanged. The new
`actions/`, `properties/` and `heading/` projects are independently authored RML, driven only
through the permitted headless `--commands` interface. Each directory has commands
and a raw session log; regenerate from that directory with the installed local CLI.
No native binary is read or committed. No CLI documentation text is included.

`test/core/oracle-actions.test.ts` checks the observations below against Anima's
scripts and independently authored conformance cases. The central oracle has no
logical-tree comparator, so these are module-owned comparisons. The central
measurement corpus/findings/thresholds remain untouched.

- Actions: 16 ordered nodes × 4 captures = 64. Roles correspond to the existing
  role spellings; label and bounds match (maximum coordinate difference 0).
  Checked, pressed, selected, expanded and disabled projections match. Slider
  values are compared as text because native SemanticData.value is textual:
  40 → 40 → 45 → 40. Native listeners explicitly assign 45/40; this verifies
  that configured sequence, not a built-in native range/clamping algorithm.
- All 16 native trait masks remain identical across the four snapshots, including
  false-state controls. The tests assert the independently recorded masks.
- **Observed focus differences: 3.** The native action scene reports button focus
  true initially and false after tap/increase/decrease; Anima preserves it. Only
  button differs in each of those three captures. Cause is not isolated. The
  properties scene keeps native control focus after tap, so this is not asserted
  as a universal native activation policy. The comparison asserts these exact
  three differences instead of dropping focus from the projection.
- Properties: raw roots 7 before / 6 after; `copy` label/hint/value change
  Before/Help/Value → After/More/Changed after semantic tap. These values match
  Anima's data-write conformance projections. Native checkbox flags 0 → 1064
  project to unchecked → mixed, required false → true and readonly false → true.
  Hidden image presence true → false matches the independent hidden probe.
  Heading metadata is level 2 on both captures, matching Anima's heading case.
- **None wrapper difference:** native has one role-none root with one child in
  each capture; Anima's none conformance case lifts its text child to the forest.
  This is the authored transparent-role contract, not claimed native tree equality.
- **Modal scope difference:** the native after tree retains 6 roots, with the
  dialog's modal bit 2048 set. Its five other roots remain. Anima's modal sibling
  case leaves only its dialog (1 root), as specified by the P3b design.

These observations are new records, not edits to any existing finding.json.

The separate heading probe binds native headingLevel to a number and writes 4 via
semantic tap. Its two captures show level 2→4; data.json independently reports
depth=4. Despite the schema not advertising headingLevel as bindable, the concrete
binding works in the installed CLI. Anima's numeric-input conformance matches both
values exactly, so no dynamic-heading oracle skip is needed.
